# IT Park Meeting Rooms — сайт и Telegram-бот

Последняя проверка и исправления: [AUDIT_REPORT_RU.md](AUDIT_REPORT_RU.md). Установка: [AUDIT_UPDATE_RU.md](AUDIT_UPDATE_RU.md).


В проекте есть сайт Meeting Rooms для бронирования с ноутбука: https://itpark-room-bot.itpark.workers.dev/ . Последняя инструкция по панели администратора и устранению ошибки `/admin`: [ADMIN_SITE_UPDATE_RU.md](ADMIN_SITE_UPDATE_RU.md). Расписание и брони общие с Telegram-ботом.

Для входа на сайт откройте Telegram-бота кнопкой с сайта или отправьте ему `/site` и нажмите присланную персональную ссылку. Вводить Telegram ID и предварительно регистрироваться в боте не нужно. Новому сотруднику сайт предложит имя, отдел и код доступа сотрудников. Для действующего профиля сайт откроется сразу. Ссылка одноразовая и действует 10 минут. Команда `/web` остаётся доступной для старых пользователей. Админ-код используется отдельно в `/admin`; токен бота никогда не вводите на сайте. В расписании кнопки ← и → переключают соседние дни в пределах доступного периода.

Логотип сайта: [IT PARK UZBEKISTAN logo](https://commons.wikimedia.org/wiki/File:IT_PARK_UZBEKISTAN_logo.png), автор ItparkUz, [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Для аватара бота загрузите `IT_PARK_Official_Logo.png` через BotFather → `/setuserpic` → выберите вашего бота. Worker не меняет аватар Telegram автоматически.

Обновление v2: профиль с отдельными кнопками редактирования и защищённая панель `/admin`. Инструкция обновления — [UPDATE_V2_RU.md](UPDATE_V2_RU.md).

Готовый проект для Cloudflare Workers + D1. Интерфейс на русском. Постоянно включённый компьютер не нужен. Исходный код хранится в GitHub, а сам бот работает на Cloudflare.

## Что умеет

- Переговорные на 5-м, 6-м и 9-м этажах.
- Регистрация по коду сотрудников; имя и отдел запоминаются.
- Выбор даты, свободного начала и длительности с шагом 30 минут.
- Несколько последовательных блоков одной бронью.
- Необязательный комментарий: для чего нужна комната.
- Проверка и явное подтверждение перед бронированием.
- Расписание с именем, отделом и комментарием; интервалы свободного времени.
- «Мои брони» и отмена с подтверждением.
- Администратор может отменить любую бронь; сохраняется, кто её отменил.
- Старые кнопки и повторные обновления Telegram не создают новую бронь.
- Состояние диалога и брони сохраняются в D1 и переживают перезапуск или публикацию новой версии.

## Как это выглядит

Главное меню: **📅 Забронировать · 🗓 Расписание · 📋 Мои брони · 👤 Мой профиль · ❓ Помощь**.

Путь сотрудника: `/start` → код доступа → имя → отдел → этаж → дата → начало → длительность → комментарий или «Пропустить» → «Подтвердить».

Профиль вводится один раз. Комментарий относится к конкретной брони. Другие сотрудники видят имя, отдел и комментарий в расписании.

## Настройки по умолчанию

| Параметр | Значение | Где изменить |
|---|---|---|
| Часовой пояс | Ташкент, UTC+5 | `src/time.js` |
| Время работы | 08:00–20:00 | `OPEN_HOUR`, `CLOSE_HOUR` в `wrangler.toml` |
| Шаг | 30 минут | логика и ограничения SQL |
| Длительность одной брони | до 4 часов | `MAX_DURATION_HOURS` |
| Горизонт | сегодня и следующие 29 дней | `BOOKING_DAYS` |
| Выходные | бронирование разрешено | текущая политика проекта |
| Черновик | устаревает через 1 час | `src/bot.js` |
| Администраторы | не заданы | `ADMIN_IDS`, Telegram ID через запятую |

Черновик не удерживает комнату. Если время занял другой сотрудник, при подтверждении бот предложит выбрать другое. Изменение брони: отменить прежнюю и создать новую. Повторяющиеся встречи, календарные интеграции и напоминания в эту версию не входят.

# Запуск: пошагово для Windows PowerShell

## 1. Установить программы и распаковать архив

Установите **Node.js 24 LTS** с https://nodejs.org/ и **Git** с https://git-scm.com/downloads. После установки откройте новый PowerShell.

Распакуйте ZIP. Откройте PowerShell в папке `itpark-room-bot`, где лежит `package.json`:

```powershell
node --version
npm --version
npm ci
npm test
```

Если PowerShell блокирует `npm.ps1`, используйте `npm.cmd` вместо `npm` и `npx.cmd` вместо `npx`. Менять политику безопасности PowerShell не требуется.

## 2. Создать бота и указать токен

1. Откройте https://t.me/BotFather и убедитесь, что это официальный BotFather.
2. Отправьте `/newbot`.
3. Название: например, `Переговорные IT Park`.
4. Выберите свободное имя пользователя, заканчивающееся на `bot`.
5. Скопируйте выданный токен.
6. В BotFather через `/setjoingroups` запретите добавление бота в группы. Бот работает в личном чате.

В папке проекта:

```powershell
Copy-Item .dev.vars.example .dev.vars
notepad .dev.vars
```

**Токен вставляется в строку `BOT_TOKEN` файла `.dev.vars`, внутри кавычек.**

```dotenv
BOT_TOKEN="сюда_токен_из_BotFather"
WEBHOOK_SECRET="сюда_случайный_секрет"
STAFF_ACCESS_CODE="сюда_код_доступа_сотрудников"
WORKER_URL="https://itpark-room-bot.ВАШ_ПОДДОМЕН.workers.dev"
```

Сгенерируйте `WEBHOOK_SECRET` этой командой и скопируйте результат в соответствующую строку:

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

`STAFF_ACCESS_CODE` — отдельный код длиной минимум 8 символов, который вы сообщите сотрудникам лично или во внутреннем канале. Не используйте для него токен бота или секрет webhook. Для простоты выберите латинские буквы и цифры.

`WORKER_URL` заполните после шага 4. Не отправляйте токен в чаты и не загружайте `.dev.vars` в GitHub. Этот файл уже исключён через `.gitignore`. Смена кода сотрудников влияет на новые регистрации; ранее зарегистрированные пользователи сохраняют доступ.

## 3. Создать бесплатную базу на Cloudflare

1. Создайте аккаунт на https://dash.cloudflare.com/ и используйте бесплатный план Workers.
2. В терминале выполните:

```powershell
npx wrangler login
npx wrangler d1 create itpark-rooms
```

Откроется браузер для авторизации. Из результата создания базы скопируйте `database_id`.

Откройте `wrangler.toml` и замените `REPLACE_WITH_YOUR_D1_DATABASE_ID` на этот ID. В файле уже есть блок `[[d1_databases]]`: второй такой же блок добавлять не нужно. Имя базы оставьте `itpark-rooms`, а binding — `DB`.

Примените схему:

```powershell
npm run db:remote
```

Это создаст таблицы, три комнаты и защиту от пересечений. При обновлениях Wrangler применяет только новые миграции. Удалять базу при обновлении бота не нужно.

## 4. Опубликовать бота и передать секреты

```powershell
npm run deploy
```

При первом запуске Cloudflare может предложить выбрать поддомен `workers.dev`. В результате появится адрес вроде `https://itpark-room-bot.example.workers.dev`.

Вставьте свой адрес в `WORKER_URL` в `.dev.vars`, без `/webhook` в конце. Теперь выполните:

```powershell
npm run secrets
npm run telegram:setup
```

`npm run secrets` передаёт `BOT_TOKEN`, `WEBHOOK_SECRET` и `STAFF_ACCESS_CODE` из вашего локального файла в защищённые настройки Cloudflare. Они не включаются в исходный код.

`npm run telegram:setup` проверяет доступность базы, регистрирует русское меню команд и связывает Telegram с вашим Worker. В конце он покажет ссылку `https://t.me/ИМЯ_БОТА`.

**Теперь компьютер можно выключить.** Откройте ссылку, нажмите Start и пройдите регистрацию.

## 5. Назначить администратора

В боте отправьте `/id`. Скопируйте свой числовой Telegram ID. Команда доступна и до регистрации.

В `wrangler.toml`:

```toml
ADMIN_IDS = "123456789"
```

Несколько администраторов: `ADMIN_IDS = "123456789,987654321"`.

После изменения:

```powershell
npm run deploy
```

Для админ-доступа также задайте секрет командой `npx wrangler secret put ADMIN_PASSCODE`. Затем в боте отправьте `/admin` и введите этот код. Сессия действует один час. Панель показывает брони, историю и сотрудников с Telegram ID, позволяет создавать бронь от своего имени и отменять конкретную бронь.

После входа администратор видит полные ID броней и Telegram ID владельцев в расписании. Для отмены:

```text
/cancel_booking ПОЛНЫЙ_ID_БРОНИ
```

Затем нажимает кнопку подтверждения. Для просмотра правил — `/help`. При назначении нового администратора он может зарегистрироваться без общего кода.

## 6. Загрузить проект в свой GitHub

Доступ к вашему GitHub из этой сессии не подключён, поэтому репозиторий автоматически не создан.

1. На https://github.com/new создайте **пустой приватный** репозиторий `itpark-room-bot`. Не добавляйте автоматически README или `.gitignore`: они уже есть.
2. В терминале папки проекта выполните:

```powershell
git init
git add .
git status
```

Проверьте, что в списке нет `.dev.vars`, `node_modules`, `.wrangler` или резервных копий базы.

```powershell
git commit -m "Add IT Park meeting room bot"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/itpark-room-bot.git
git push -u origin main
```

Замените `YOUR_USERNAME` на имя вашего GitHub-аккаунта. Git может открыть браузер для входа. Если Git просит имя и email автора, задайте свои значения командами `git config user.name` и `git config user.email`, затем повторите commit.

В проекте есть GitHub Actions: тесты запускаются при push и pull request. В `Actions` также есть ручной workflow **Deploy manually**. Для него в GitHub → Settings → Secrets and variables → Actions добавьте:

- `CLOUDFLARE_ACCOUNT_ID` — ID вашего аккаунта Cloudflare.
- `CLOUDFLARE_API_TOKEN` — API-токен Cloudflare, ограниченный нужным аккаунтом, с разрешениями Workers Scripts: Edit, D1: Edit и Account Settings: Read.

Первый запуск, создание D1, передача секретов бота и настройка webhook всё равно выполняются по шагам выше. Workflow предназначен для последующих публикаций по кнопке; push сам по себе не выкладывает изменения в рабочий бот. Токен Telegram в GitHub добавлять не требуется.

## 7. Проверить перед передачей всем сотрудникам

1. Со своего аккаунта забронируйте завтрашние 10:00–11:00 на 5-м этаже.
2. Со второго аккаунта откройте ту же дату: занятое начало не должно предлагаться.
3. Для проверки гонки заранее откройте экран подтверждения одного свободного времени на двух аккаунтах. Подтвердите обе заявки: только одна должна получить бронь.
4. Проверьте расписание и «Мои брони».
5. Отмените бронь и проверьте, что время снова предлагается.
6. Проверьте 6-й и 9-й этажи.
7. Поделитесь ссылкой на бота и кодом сотрудников.

Реальные вызовы Telegram и публикация в ваш аккаунт требуют вашего токена и доступа Cloudflare. В архиве они не настроены. Локальные автоматические проверки не заменяют этот короткий запуск с двумя реальными аккаунтами.

# Надёжность

Уникальный ключ `(room_id, day, minute)` в `booking_slots` не позволяет двум броням занять один получасовой блок. Триггер создаёт все блоки при вставке брони. Конфликт хотя бы одного блока откатывает операцию целиком. Отмена освобождает все блоки в той же транзакции.

Состояние пользователя, бронь и ответ бота записываются одной транзакцией `D1.batch()`. Проверка версии состояния защищает от параллельных нажатий. `update_id` предотвращает повторное выполнение полученного события. Старые кнопки имеют истёкший идентификатор шага. Telegram настроен на одну webhook-связь для упорядоченного диалога; защита базы не зависит от этого ограничения.

При ошибке Telegram API бот возвращает HTTP 503, чтобы Telegram повторил доставку. Если сообщение уже отправлено, но запись о доставке не успела сохраниться, пользователь может получить повторное подтверждение; второй брони при этом не создаётся. После длительного сбоя актуальное состояние можно проверить через `/my`.

Резервирование и отправка сообщения в Telegram — разные системы, поэтому абсолютной гарантии бесперебойности нет. Бесплатные квоты, доступность Cloudflare и Telegram, а также корректные секреты остаются условиями работы.

- Workers: 100 000 запросов в день, общая квота аккаунта; 10 мс CPU на запрос.

Для нескольких переговорных при обычной офисной нагрузке это разумный бесплатный вариант. Следите за Usage в панели; при исчерпании бесплатных квот возможны ошибки до сброса лимитов. Не включайте платный план, если не хотите платных расходов.

# Обновления, резервные копии и диагностика

После изменения кода: `npm test`, затем `npm run deploy`. После добавления SQL-миграции сначала `npm run db:remote`. Изменения начальной миграции не применяются повторно: создавайте новую миграцию.

Локальная разработка: `npm run db:local`, затем `npm run dev`. Локальный адрес сам по себе недоступен Telegram; основной путь запуска выше использует публичный Worker. Не переключайте рабочий webhook на локальную среду без необходимости.

Резервная копия из папки проекта:

```powershell
mkdir backups
npx wrangler d1 export itpark-rooms --remote --output=backups/rooms-backup.sql
```

Если папка уже существует, пропустите `mkdir`. Храните копию отдельно; в ней есть данные сотрудников. Выбирайте новое имя для каждой копии.

Диагностика:
- `/health` по адресу Worker должен возвращать `{"ok":true}`. Это проверка базы, а не Telegram-соединения.
- Если бот молчит, проверьте успешность `npm run secrets`, затем повторите `npm run telegram:setup`.
- Проверьте, что `WEBHOOK_SECRET` в Cloudflare и локальном файле одинаковый.
- Не запускайте второй экземпляр бота с тем же токеном через polling: webhook должен принадлежать этому проекту.
- Логи Worker: `npx wrangler tail`. Код не печатает токены, текст обновлений или персональные данные.
- При смене токена через BotFather обновите `.dev.vars`, выполните `npm run secrets` и `npm run telegram:setup`.
- Смена `ADMIN_IDS` требует `npm run deploy`.

Добавление комнаты после первого запуска делается новой SQL-миграцией, например `INSERT INTO rooms(id,name) VALUES(10,'Переговорная · 10-й этаж');`. Число в `id` — уникальный идентификатор, поэтому для двух комнат на одном этаже используйте разные ID и понятные названия. Отключение комнаты: `UPDATE rooms SET active=0 WHERE id=...;`. Существующие брони не удаляются, владельцы по-прежнему могут отменить их через «Мои брони».

# Состав проекта

- `src/bot.js` — русские диалоги и транзакции.
- `src/worker.js` — webhook, проверка секрета, доставка ответа и очистка старых квитанций.
- `src/time.js` — даты, часовой пояс и проверки интервала.
- `migrations/0001_initial.sql` — таблицы, комнаты, ограничения и триггеры.
- `scripts/` — безопасная передача секретов и настройка Telegram.
- `tests/` — проверки на SQLite и локальной D1 в Miniflare.
- `.github/workflows/` — тестирование и ручная публикация.
- `.dev.vars.example` — шаблон секретов без реальных значений.
- `wrangler.toml` — настройки Cloudflare и часы работы.

Runtime-код не использует сторонние библиотеки; Wrangler и Miniflare нужны только для разработки, тестирования и публикации. Версии зависимостей зафиксированы в `package-lock.json`.
