# Проверки проекта

Дата: 28.09.2026. Среда: Linux, Node.js 24.19.0.

`npm test`: **26 тестов успешно, 0 ошибок**.

Проверены:
- регистрация, сохранение имени и отдела, необязательный комментарий;
- 25 одновременных заявок на один интервал на SQLite: ровно одна бронь;
- 12 одновременных подтверждений в локальной Cloudflare D1 / Miniflare: ровно одна бронь, два занятых получасовых блока, 12 квитанций обработки;
- частичное пересечение и отсутствие частично сохранённых блоков;
- соседние интервалы и бронирование разных комнат на одно время;
- повторный update_id и повторное нажатие подтверждения;
- повторная доставка после временной ошибки Telegram API (API подменён в тесте);
- отмена владельцем, освобождение блоков и повторное бронирование;
- запрет отмены чужой брони обычным сотрудником;
- отмена администратором с сохранением его ID;
- старые кнопки, неподходящие интервалы, прошедшее время;
- часовой пояс, смена даты и границы горизонта;
- ограничение попыток ввода кода, игнорирование групповых сообщений;
- устаревшие обновления и случайный update_id после недели бездействия;
- длина комментария и вывод текста без HTML-интерпретации;
- секрет webhook, невалидный JSON и health endpoint;
- выход из редактирования профиля.

`wrangler deploy --dry-run`: сборка прошла, binding DB и параметры конфигурации распознаны.

Это локальные проверки. Публикация в пользовательский Cloudflare, установка webhook для настоящего токена и проверка с двумя Telegram-аккаунтами ещё не выполнялись. Их шаги есть в README.md. GitHub-репозиторий из этой сессии не создан.

## Дополнительные проверки v2

Профиль открывается без ввода и сохраняется после /start; имя и отдел редактируются независимо. Админ-панель требует и разрешённый ID, и код. Проверены списки и карточки броней, Telegram ID, история отмены, создание брони администратором, блокировка неправильных кодов, выход, истечение сессии и повторная проверка прав при отмене. Обычный сотрудник не получает административные данные через поддельные кнопки.

Обновление v2 ещё не опубликовано в рабочем боте: публикацию выполняет владелец по UPDATE_V2_RU.md.

## Сайт бронирования

Проверены однократный код входа в локальной D1, параллельное погашение кода, защищённая cookie-сессия, общие с ботом брони и слоты, отмена, профиль, блокировка чужого Origin и неправильной даты. Рендер основного HTML, CSS, JS проверен в Worker. Публикацию в рабочем аккаунте выполняет владелец по WEBSITE_UPDATE_RU.md.
