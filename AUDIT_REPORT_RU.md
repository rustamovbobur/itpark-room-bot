# Проверка IT Park Meeting Rooms — 28 сентября 2026

## Область проверки

Проверена текущая локальная копия проекта: Telegram-бот, сайт, API, SQL-ограничения бронирований, авторизация сотрудников и администраторов, обработка ошибок и повторных запросов. Реальные рабочие брони не создавались и не отменялись.

**Итог: 45 автоматических тестов прошли, 0 ошибок.** Проверка сборки `wrangler deploy --dry-run` прошла. Это подтверждает проверенные сценарии, а не отсутствие всех возможных ошибок.

## Найдено и исправлено

| № | Проблема | Исправление |
|---|---|---|
| 1 | Логотип открывал Wikimedia вместо главной страницы. | Теперь ведёт на `/` в том же окне. Атрибуция перенесена на отдельную страницу «О сайте и логотипе» в профиле. |
| 2 | Изменение профиля на сайте не меняло версию записи пользователя. Одновременное действие бота могло записать старые имя и отдел поверх новых. | Веб-изменения повышают версию, поэтому устаревшая транзакция бота отклоняется и пересчитывается. |
| 3 | После регистрации на сайте могло остаться незавершённое состояние регистрации в боте. | При завершении веб-регистрации состояние переводится в главное меню. |
| 4 | Вход по персональной ссылке не ограничивал угадывание кода сотрудников. | Не более пяти попыток за 15 минут для Telegram ID; новая ссылка не сбрасывает ограничение. |
| 5 | Ограничение попыток админ-пароля зависело от IP. Назначенный администратор мог обойти его сменой адреса. | Счётчик привязан к Telegram ID. |
| 6 | JSON `null`, массивы и другие неподходящие тела запросов могли вызвать необработанное исключение. | Проверяется объект JSON. Входящий поток ограничен 4096 байтами до полного чтения. |
| 7 | В открытой форме бронирования использовалась текущая дата страницы. Автоматическая смена даты в полночь могла перенести бронь на другой день. | Форма сохраняет выбранную дату при открытии. |
| 8 | Более старый ответ расписания мог прийти последним и заменить свежие данные. При смене даты старые ячейки кратковременно оставались нажимаемыми. | Ответы имеют порядковый номер; старые ответы игнорируются. Ячейка не открывает бронь, если дата отображённой сетки уже не соответствует выбранной. |
| 9 | При истечении обычной веб-сессии сайт оставался на неработающем расписании. | Возвращается форма входа с объяснением. |
| 10 | Обновление страницы во время первого заполнения профиля теряло уже проверенную Telegram-ссылку. | Незавершённая ссылка временно сохраняется в sessionStorage текущей вкладки и удаляется после использования. Срок и одноразовость по-прежнему проверяет сервер. |
| 11 | Ошибка базы могла вернуть клиенту необработанную ошибку вместо JSON. | Worker возвращает понятную ошибку 503 без внутренних данных. |
| 12 | `/health` проверял только наличие комнат и мог сообщать успех при отсутствующих миграциях сайта. | Проверяется наличие необходимых таблиц и колонки аудита бронирований. |
| 13 | JS/CSS кешировались пять минут, поэтому после обновления могла открываться смесь новой HTML и старого JavaScript. | Для JS/CSS установлен `no-cache`, требующий перепроверки ресурса. |
| 14 | Скрипт загрузки секретов игнорировал ADMIN_PASSCODE даже при его наличии в локальной конфигурации. | Если значение задано в окружении, оно включается в загрузку секретов. В код значение не записывается. |
| 15 | Границы даты в админ-панели не обновлялись после полуночи. | Обновляются вместе с основной датой сайта. |

Дополнительно: неверные типы даты и входящих событий бота обрабатываются устойчивее. Вкладка администратора повторно проверяет сессию при открытии.

### Пароль в старой инструкции

Предыдущая инструкция `ADMIN_SITE_UPDATE_RU.md` содержала выбранный админ-пароль. Это было ошибкой: он мог попасть в GitHub вместе с документацией. Значение удалено из новой инструкции. Если старый файл уже отправлен в GitHub, удаление строки не стирает историю коммитов. Рекомендуется установить новый личный пароль через `npx.cmd wrangler secret put ADMIN_PASSCODE`. Ограничение по ADMIN_IDS продолжает действовать.

## Ограничения проверки

- Это не проверка с реальным входом в рабочий Telegram и Cloudflare. Запросы к рабочему сайту из этой среды получили 403 или тайм-аут; по этим ответам нельзя заключить, что сайт недоступен сотрудникам.
- Полная визуальная проверка Chrome/мобильного браузера не выполнена: загрузка тестового Chromium завершилась ошибкой. Тесты клиента используют DOM-симулятор, который не проверяет отрисовку CSS.
- Список сотрудников в админ-панели ограничен 500 записями. Для большего штата понадобится поиск или пагинация.
- При обрыве связи после отправки сообщения Telegram возможен повтор сообщения, хотя повторная бронь защищена базой.
- Бронь, созданная администратором для сотрудника, видна в «Мои брони»; отдельное Telegram-уведомление пока не отправляется.

После публикации вручную проверьте вход, логотип, стрелки дат, создание одной тестовой брони и её отмену, а также открытие админ-панели. При проверке используйте свободный будущий интервал.
